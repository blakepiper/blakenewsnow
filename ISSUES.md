# Blake News Now - Issues & Improvements Report

Generated by diagnostic tests. This document outlines discovered issues, their severity, and recommended fixes.

---

## Critical Issues (Must Fix for Production)

### 1. Hardcoded API URL
**Severity:** High
**Files:** All components using `API_BASE`

The API URL `http://localhost:3001` is hardcoded throughout the codebase. This will break in production.

**Fix:**
```typescript
// src/config.ts
export const API_BASE = import.meta.env.VITE_API_URL || 'http://localhost:3001';

// .env.development
VITE_API_URL=http://localhost:3001

// .env.production
VITE_API_URL=https://api.blakenewsnow.com
```

### 2. CORS Configuration
**Severity:** High
**File:** `server/proxy.cjs`

CORS is currently allowing all origins (`cors()`). In production, this is a security risk.

**Fix:**
```javascript
app.use(cors({
  origin: process.env.NODE_ENV === 'production'
    ? ['https://blakenewsnow.com']
    : true,
  credentials: true,
}));
```

### 3. Settings setTimeout Without Cleanup
**Severity:** Medium
**File:** `src/components/Settings.tsx`

The `setTimeout` for the "Saved!" feedback message doesn't get cleaned up if the component unmounts.

**Fix:**
```typescript
useEffect(() => {
  if (!locationSaved) return;
  const timer = setTimeout(() => setLocationSaved(false), 2000);
  return () => clearTimeout(timer);
}, [locationSaved]);
```

## Accessibility Issues

### 1. Low Contrast Text
**Severity:** Medium
**Files:** Multiple components

Text with `text-white/20` or `text-white/30` opacity on dark backgrounds fails WCAG contrast requirements.

**Affected classes:** `text-white/20`, `text-white/30`, `text-white/40`

**Fix:** Increase to minimum `text-white/50` for small text or `text-white/60` for body text.

### 2. Missing Button Accessibility
**Severity:** Medium
**Files:** `KeyboardHelp.tsx`, `Settings.tsx`, `ArticleReader.tsx`

Some buttons lack `aria-label` or `title` attributes.

**Fix:** Add descriptive labels:
```tsx
<button
  onClick={onClose}
  aria-label="Close settings"
  title="Close settings"
>
```

### 3. Images Missing Alt Text
**Severity:** Medium
**File:** `src/components/Weather.tsx`

Radar and map images use `alt=""` which provides no context for screen readers.

**Fix:**
```tsx
<img src={radarUrl} alt="Weather radar for current location" />
<img src={mapUrl} alt="Map background" aria-hidden="true" />
```

## Performance Issues

### 1. No Loading States for Data Components
**Severity:** Low
**Files:** `Headlines.tsx`, `Financial.tsx`, `Predictions.tsx`

Some components show nothing while loading, causing layout shift.

**Fix:** Add skeleton loading states:
```tsx
if (loading) {
  return (
    <div className="space-y-2">
      {[...Array(5)].map((_, i) => (
        <div key={i} className="skeleton h-16 rounded" />
      ))}
    </div>
  );
}
```

### 2. Magic Number Timeouts
**Severity:** Low
**Files:** Multiple

Refresh intervals are hardcoded numbers like `60000` instead of named constants.

**Fix:**
```typescript
// src/config.ts
export const REFRESH_INTERVALS = {
  headlines: 60 * 1000,  // 1 minute
  markets: 30 * 1000,    // 30 seconds
  weather: 5 * 60 * 1000, // 5 minutes
} as const;
```

### 3. Inline Event Handlers
**Severity:** Low
**File:** `Settings.tsx`

Multiple inline `onClick` handlers create new functions on every render.

**Fix:** Use `useCallback` for handlers passed to child components.

## Missing Features

### 1. Error Boundaries
**Priority:** High

No error boundaries exist. A single component crash will take down the entire app.

**Fix:** Create error boundary wrapper:
```tsx
// src/components/ErrorBoundary.tsx
class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  render() {
    if (this.state.hasError) {
      return <div>Something went wrong. <button onClick={() => window.location.reload()}>Reload</button></div>;
    }
    return this.props.children;
  }
}
```

### 2. Settings Validation
**Priority:** Medium
**File:** `src/stores/settings.ts`

No validation on settings loaded from localStorage. Corrupted data will cause crashes.

**Fix:**
```typescript
function validateSettings(data: unknown): Settings | null {
  if (typeof data !== 'object' || data === null) return null;
  // Validate required fields...
  return data as Settings;
}
```

### 3. Settings Migration
**Priority:** Medium
**File:** `src/stores/settings.ts`

No versioning for settings schema. Changes to the schema will break existing user settings.

**Fix:**
```typescript
const SETTINGS_VERSION = 1;

interface StoredSettings {
  version: number;
  data: Settings;
}

function migrateSettings(stored: StoredSettings): Settings {
  if (stored.version < 1) {
    // Apply migrations
  }
  return stored.data;
}
```

### 4. Responsive Design
**Priority:** Low

No responsive breakpoints. The app won't work well on tablets or smaller screens.

**Fix:** Add Tailwind breakpoints for different screen sizes:
```tsx
<div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3">
```

## Server-Side Issues

### 1. Missing Security Headers
**Priority:** Medium
**File:** `server/proxy.cjs`

No security headers (CSP, X-Frame-Options, etc.).

**Fix:**
```javascript
const helmet = require('helmet');
app.use(helmet());
```

### 2. No Rate Limiting
**Priority:** Medium
**File:** `server/proxy.cjs`

API endpoints have no rate limiting. Could be abused or accidentally overload external APIs.

**Fix:**
```javascript
const rateLimit = require('express-rate-limit');
app.use('/api/', rateLimit({
  windowMs: 60 * 1000,
  max: 100,
}));
```

### 3. Inconsistent Request Timeouts
**Priority:** Low
**File:** `server/data-feeds.cjs`

Not all external API calls have explicit timeouts.

**Fix:** Add timeout to all fetch calls:
```javascript
const { data } = await fetch(url, { timeout: 10000 });
```

## Recommended Architecture Improvements

### Near-Term
1. **Add React Query/SWR** - Replace manual fetch logic with a data fetching library
2. **Add error boundaries** - Prevent full app crashes
3. **Extract API_BASE to env** - Support multiple environments
4. **Add loading skeletons** - Better perceived performance

### Medium-Term
1. **Add Zustand/Jotai** - Proper state management as complexity grows
2. **Add proper logging** - Replace console.log with structured logging
3. **Add service worker** - Offline support and faster loading
4. **Add unit tests** - Test hooks and utilities

### Long-Term
1. **Add E2E tests** - Playwright/Cypress for critical flows
2. **Add Storybook** - Component documentation
3. **Consider SSR/SSG** - Next.js for SEO and performance
4. **Add WebSocket** - Real-time updates instead of polling
