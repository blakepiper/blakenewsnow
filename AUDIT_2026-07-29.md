# Blake News Now revival audit

Date: 2026-07-29

## What was wrong

### Stale stories could become the newest story

The old regex parser used `new Date()` whenever an item had no recognized publication date. CNN's abandoned top-stories feed still returned 2023 stories, and several entries had no item-level date. Those entries were assigned the current millisecond and sorted above real current reporting.

The live reproduction put these at ranks 1-3:

1. A 2023 Dominion lawsuit update
2. A 2023 Russia and Ukraine live-blog entry
3. A 2023 opinion piece about the 2024 election

### Several configured sources were dead

- CNN's old RSS feed was an archive from 2023.
- Reuters returned HTTP 404.
- The RSSHub AP bridge returned HTTP 403.
- Washington Post exceeded the five-second request timeout.
- Daily Wire returned no parseable items.
- Reddit's anonymous JSON endpoints returned HTTP 403.

### Source settings did not affect the feed

The switches only changed local storage. `useUnifiedFeed` never read them, so disabled sources continued to appear.

### Desktop ranking was hard to read

The list was split into ranks 1-25 on the left and 26-50 on the right. The second newest item appeared far below the first instead of beside it.

### The build was already broken

TypeScript rejected an unused `onSetLayout` prop in `Settings.tsx`.

### Refreshes could stampede upstream services

Several clients opening while the cache was cold could trigger duplicate headline, Reddit, Hacker News, 4chan, market, and prediction requests.

## Remaining priorities

### 1. Add authenticated Reddit access

Anonymous Reddit feeds can still return HTTP 403 or 429. Add Reddit OAuth credentials through environment variables and use the documented API. Until then, cached Atom data is best-effort.

### 2. Expose per-source health

The API logs failures, but the UI cannot distinguish a quiet source from a failed source. Add a `/api/feed-status` response with last success, item count, latency, last error, and cache age. Show a compact status view in settings.

### 3. Add component and browser tests

The new RSS tests cover the original failure, but the feed hook, source switches, keyboard flow, search, settings persistence, and responsive layout still need Vitest/Testing Library and Playwright coverage.

### 4. Split the server module

`server/data-feeds.cjs` still owns news, social, markets, weather, radar, and predictions. Separate modules would make retry, health, cache, and unit-test policies easier to reason about.

### 5. Decide how long this branch should stay on MUI v4

MUI 4.12.4 is intentionally pinned for work training and no longer receives active development. The application now uses its supported React 17 generation and currently has zero production dependency advisories. For a long-lived public deployment, plan a separate MUI 5+ upgrade after the version-specific learning goal is complete.

### 6. Resolve development-only audit findings

The remaining `npm audit` findings are in the ESLint toolchain and require a breaking ESLint 10 upgrade. They are not shipped in the production bundle. Upgrade the lint stack in a separate focused change.

### 7. Finish resilient UI states

The unified feed has loading, empty, and full-failure states, but partial upstream failure is silent. Sidebar sections also need compact error boundaries and retry actions.
